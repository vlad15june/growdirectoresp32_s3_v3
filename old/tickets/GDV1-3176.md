# GDV1-3176: Implement AddWifi Module Command

**Jira Link:** https://growdirector.atlassian.net/browse/GDV1-3176

---

## Ticket Description

### Problem Statement

The `AddWifi` module command is end-to-end broken in two places:

1. **`ModuleCommandExecutionUseCase::handleAddWifi()`** parses `ssid` and `password` from the command options but never calls anything — the body is a stub returning `DONE` with a commented-out `TODO`.
2. **`WiFiManager::addWifiNetwork()`** only overwrites the single EEPROM slot (`Settings::setSsid` / `setPassword`) and has its own `TODO: store the new WiFi credentials in a file`. It does not persist to SPIFFS, so all previously saved networks are silently lost on every call. Likewise, **`WiFiManager::setupWifiConnection()`** has a `TODO: add creds from file` — it never loads previously stored networks back into `WiFiMulti` at boot.

As a result, issuing `AddWifi` from the backend replaces the one stored network in EEPROM and returns `DONE`, but the module can never accumulate multiple known networks and reconnect to the best available one.

The full multi-network implementation already exists in the old firmware (`addWifiToFile`, `addWifiNetworks`) and is preserved as a dead-code comment block at the bottom of `WiFiManager.h`. It needs to be ported to the new clean-architecture layer.

### Solution

Complete `WiFiManager` and connect it to `ModuleCommandExecutionUseCase`:

1. **`WiFiManager`** — add `ISpiffsAdapter*` dependency; implement multi-network SPIFFS persistence:
   - `addWifiNetwork()` — append to `/wifiNetworks.json` (no duplicate check by ssid), register in `WiFiMulti` immediately via `_wifiAdapter->addNetwork()`; no longer clobber EEPROM
   - `setupWifiConnection()` — load all networks from `/wifiNetworks.json` into `WiFiMulti` before connecting, fallback to the single EEPROM network if the file is empty or missing
2. **`ModuleCommandExecutionUseCase`** — add `IWifiManager*` dependency; call `wifiManager->addWifiNetwork()` in `handleAddWifi()`
3. **`globals.h`** — pass `&spiffsAdapter` to `WiFiManager` and `&wifiManager` to `ModuleCommandExecutionUseCase`

### Technical Approach

Leverage `ISpiffsAdapter` (already available with `readSPIFFSstr` / `RewriteToFile`) and the existing `IWifiAdapter::addNetwork()` / `connectToNetworks()`:

1. Add `ISpiffsAdapter*` to `WiFiManager` constructor alongside existing dependencies
2. Implement `loadNetworksFromFile()` — private helper: read `/wifiNetworks.json`, parse JSON array, call `_wifiAdapter->addNetwork()` for each entry, return count loaded
3. Implement `saveNetworksToFile()` — private helper: accept new `{ssid, password}`, read existing file, deduplicate by ssid, append, rewrite via `RewriteToFile()`
4. Update `addWifiNetwork()` to call `saveNetworksToFile()` + `_wifiAdapter->addNetwork()`; stop touching EEPROM
5. Update `setupWifiConnection()` to call `loadNetworksFromFile()`; if count == 0, fall back to EEPROM `getSsid/getPassword`
6. Add `IWifiManager*` to `ModuleCommandExecutionUseCase`; implement `handleAddWifi()` body
7. Wire everything in `globals.h`

### Related Tickets

- None directly related — this completes two stubbed implementations that were scaffolded but never finished

## Development Plan

### **Overview**
Two layers need completing. The lower layer (`WiFiManager`) needs to gain SPIFFS-backed multi-network persistence mirroring the old `addWifiToFile` / `addWifiNetworks` functions from v1; the file format is a JSON array `[{"ssid":"...","password":"..."},...]`. The upper layer (`ModuleCommandExecutionUseCase`) simply needs `IWifiManager*` injected and a one-liner call in `handleAddWifi()`. `MockSpiffsAdapter` is already available for testing `WiFiManager`, and `MockWiFiManager` is already available for testing the use case.

### **Instructions:**

1. **Extend `IWifiManager` interface** (if needed)
   - Verify `addWifiNetwork(ssid, password)` signature is sufficient — no changes expected

2. **Complete `WiFiManager`**
   - Add `ISpiffsAdapter*` and `IJsonConverter*` constructor parameters (defaults `nullptr`, append after existing params)
   - Add private helper `int loadNetworksFromFile()`:
     - Read `/wifiNetworks.json` via `_spiffsAdapter->readSPIFFSstr()`; return 0 if empty
     - Call `_jsonConverter->wifiNetworksFromJson(fileContent, networks)` → `std::vector<WifiNetworkEntry>`
     - For each entry call `_wifiAdapter->addNetwork(entry.ssid.c_str(), entry.password.c_str())`
     - Return count of networks loaded
   - Add private helper `bool saveNetworkToFile(const char* ssid, const char* password)`:
     - Read current file; call `_jsonConverter->wifiNetworksFromJson()` into a `vector<WifiNetworkEntry>`
     - Skip if an entry with the same `ssid` already exists (deduplicate)
     - Append `WifiNetworkEntry{ssid, password}`; call `_jsonConverter->wifiNetworksToJson(networks)` to reserialize
     - Write result via `_spiffsAdapter->RewriteToFile(WIFI_NETWORKS_FILE, json.c_str())`
   - Update `addWifiNetwork()`:
     - Call `saveNetworkToFile(ssid, password)`
     - Call `_wifiAdapter->addNetwork(ssid, password)` to register in the active `WiFiMulti` session
     - Remove the old `_settings->setSsid/setPassword` calls and the `TODO` comment
   - Update `setupWifiConnection()`:
     - Call `loadNetworksFromFile()` before connecting
     - If count == 0: fallback to `_settings->getSsid/getPassword` + `_wifiAdapter->addNetwork()`
     - Remove the `TODO: add creds from file` comment
   - The old dead-code comment block at the bottom of the file can be removed
