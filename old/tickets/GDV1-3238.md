# GDV1-3238: S3 not send structure when change sensor

**Jira Link:** https://growdirector.atlassian.net/browse/GDV1-3238

---

## Ticket Description

### Problem Statement

When sending a `SetSensorModel` command to select a sensor type, the module successfully saves the sensor to the repository and marks the command as completed. The code DOES attempt to send the module structure to the API server, but it sends the OLD structure that was loaded during module initialization. The `ModuleStructure` object in memory is not automatically refreshed when sensors are added/removed, so the backend receives outdated information without the new sensor. The structure only reflects changes after a module reboot when `fillModuleStructure()` is called again during initialization.

### Solution

Add methods to ModuleStructure for direct data manipulation:
- Add `addSensor()`, `removeSensorsByPin()` methods to ModuleStructure
- Match repository operations: remove by pin, then add new sensor
- ModuleStructure tracks changes matching repository state
- No external dependencies - direct structure updates

### Technical Approach

Direct structure updates mirroring repository operations:
1. Add `addSensor(SensorEntity)` method to ModuleStructure - adds sensor to nodes
2. Add `removeSensorsByPin(int pin)` method - removes ALL sensors on this pin from nodes
3. In use case: first `moduleStructure->removeSensorsByPin(pin)`, then `moduleStructure->addSensor(newSensor)`
4. Matches repository logic: delete old sensors by pin → save new sensor
