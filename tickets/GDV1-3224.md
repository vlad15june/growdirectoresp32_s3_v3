# GDV1-3224: Per-Feature Configurable Logging Channels (MQTT/Serial/Both)

**Jira Link:** https://growdirector.atlassian.net/browse/GDV1-3224

---

## Ticket Description

### Problem Statement

The current logging system has a global channel configuration (`MqttLoggerMode`) that applies to all log output uniformly - logs go either to MQTT only, Serial only, or both channels. This limitation means that when debugging specific features, developers cannot selectively route different debug features to appropriate channels. For example, network-related debug output may be better suited for Serial monitoring during hardware debugging, while high-level business logic logs should go to MQTT for cloud monitoring. The inability to configure logging channels per debug feature reduces flexibility and makes debugging workflows inefficient.

### Solution

Implement per-feature logging channel configuration that:
- Extends the existing debug feature system to include channel configuration for each registered debug feature
- Allows specifying logging channel (`MQTT`, `Serial`, or `Both`) when registering each debug feature via `IDebugSystem`
- Stores channel preference as part of debug feature metadata
- Provides API for dynamic channel configuration updates during runtime
- Modifies logger methods to check debug feature channel settings before outputting logs
- Maintains backward compatibility with existing global `MqttLoggerMode` as fallback for non-feature-specific logs
- Examples of different channel configurations:
  - **MQTT only** for `ip_local_change` - cloud monitoring of network changes
  - **Serial only** for `sensor_error` - local hardware debugging
  - **Both channels** for `module_command` - comprehensive command tracking

### Technical Approach

Leverage existing debug feature and logging infrastructure to:
1. Extend `IDebugFeature` interface to include channel configuration property
2. Modify `DebugFeature` class to store and manage `MqttLoggerMode` per feature
3. Update `IDebugSystem` interface to accept channel parameter during feature registration
4. Enhance `DebugSystem::registerFeature()` to initialize features with specified channel
5. Add API methods to get/set channel configuration for existing debug features
6. Modify logging flow to check both feature enabled state AND channel configuration before output
7. Update existing feature registrations to specify appropriate channels
8. Maintain global `MqttLoggerMode` as default for non-feature-specific logging

## Development Plan

### **Overview**
Enhance the existing debug feature system by adding per-feature logging channel configuration. The implementation extends `IDebugFeature` and `DebugFeature` classes to store `MqttLoggerMode` alongside the enabled state for each registered debug feature. The `ILogger` interface will be updated to accept optional feature name parameter, allowing the logger to query the debug system for the feature's channel configuration and route logs accordingly. This approach maintains clean separation between debug feature management (DebugSystem) and log output execution (MqttLogger) while providing flexible per-feature channel control.

### **Implementation Details:**

#### **Channel Resolution Flow:**
1. Logger receives call with feature name → Queries debug system for feature configuration
2. Debug system returns `MqttLoggerMode` for the feature
3. Logger evaluates channel configuration:
   - **MqttOnly**: Output only to MQTT topic (if connected)
   - **SerialOnly**: Output only to Serial monitor
   - **MqttAndSerial**: Output to both channels
4. If feature not found or debug system not available → Fall back to global `_mode`

#### **Feature Registration Example:**
```cpp
// In DebugSystem::initializeFeatures()

// MQTT only - for cloud monitoring
registerFeature(DebugFeatures::IP_CHANGE_DEBUG, "ip_local_change", true, MqttLoggerMode::MqttOnly);
registerFeature(DebugFeatures::MODULE_COMMAND_DEBUG, "module_command", true, MqttLoggerMode::MqttOnly);

// Serial only - for local hardware debugging
registerFeature(DebugFeatures::SENSOR_ERROR_DEBUG, "sensor_error", false, MqttLoggerMode::SerialOnly);
registerFeature(DebugFeatures::BUTTON_DEBUG, "button", false, MqttLoggerMode::SerialOnly);

// Both channels - for comprehensive logging
registerFeature(DebugFeatures::RULE_DEBUG, "rule", true, MqttLoggerMode::MqttAndSerial);
registerFeature(DebugFeatures::DEVICE_COMMAND_DEBUG, "device_command", true, MqttLoggerMode::MqttAndSerial);
```

#### **Logger Usage Pattern:**
```cpp
// Old style - uses global logger mode (still supported)
if (debugSystem.isFeatureEnabled(DebugFeatures::IP_CHANGE_DEBUG)) {
    logger->println("ip_local_change", "IP address changed");
}

// New style - uses feature-specific channel
if (debugSystem.isFeatureEnabled(DebugFeatures::IP_CHANGE_DEBUG)) {
    logger->printlnDebug(DebugFeatures::IP_CHANGE_DEBUG, "ip_local_change", "IP address changed");
}
// Automatically outputs only to MQTT if feature configured with MqttOnly

// Sensor error example
if (debugSystem.isFeatureEnabled(DebugFeatures::SENSOR_ERROR_DEBUG)) {
    logger->printfDebug(DebugFeatures::SENSOR_ERROR_DEBUG, "sensor_error", 
                       "Sensor %s read failed: %s", sensorUid, errorMsg);
}
// Automatically outputs only to Serial if feature configured with SerialOnly
```

#### **Backward Compatibility Strategy:**
- All existing `print()`, `println()`, `printf()` methods remain unchanged
- New `printDebug()`, `printlnDebug()`, `printfDebug()` methods added for feature-aware logging
- Global `MqttLoggerMode` remains as fallback for non-feature logging
- If `IDebugSystem*` is nullptr, all methods fall back to global mode
- Gradual migration: existing code continues working, new code can use feature-specific methods
