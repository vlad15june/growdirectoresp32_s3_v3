# Подключение метеодатчика HCD6817Z (7-в-1)

**Affects:** backend, firmware

## Short

Подключить к модулю метеодатчик HCD6817Z Seven-in-one (RS-485, Modbus RTU, 9600 8N1, адрес по умолчанию `0xFF`): температура и влажность воздуха, атмосферное давление, скорость и направление ветра, накопленные осадки (ковшевой датчик), освещённость и/или солнечная радиация. Все 8 каналов читаются одним запросом FC03 по регистрам `0x0009–0x0010` и укладываются в существующий data-driven `ModbusSensorReader` — основной объём работ это публикация модели датчика на backend и валидация, а не новый код прошивки.

Даташит: `/home/vlad/dev/sensors/06-HCD6817Z Seven-in-one Meteorological Sensor.pdf`.

## Description

Каталог моделей датчиков живёт на backend; модуль скачивает его через `GET /api/v1/Hardware/sensor_models`, кеширует в SPIFFS (`sensorTypes.json`) и ведёт сканирование/опрос полностью по данным модели. Ближайший аналог — метеостанция XF600A (см. `doc/sensor-models.md`), у которой идентичный стиль карты регистров `0x0009+`.

Карта регистров HCD6817Z (FC03, все значения u16, high byte first):

| Канал | Регистр | Множитель | Оффсет | Ед. | Диапазон |
|---|---|---|---|---|---|
| Температура воздуха | 0x0009 | 0.01 | −40 | °C | −40…85 |
| Влажность воздуха | 0x000A | 0.01 | 0 | %RH | 0…100 |
| Атмосферное давление | 0x000B | 0.1 | 0 | hPa | 300…1100 |
| Скорость ветра | 0x000C | 0.01 | 0 | m/s | 0…60 |
| Направление ветра | 0x000D | 0.1 | 0 | ° | 0…360 |
| Осадки (накопление) | 0x000E | 0.1 | 0 | mm | 0…4 мм/мин |
| Солнечная радиация | 0x000F | 1.0 | 0 | W/m² | 0…2000 |
| Освещённость | 0x0010 | 0.01 | 0 | kLux | 0…200 |

Прочие параметры из даташита:

- Смена Modbus-адреса: FC06, регистр `0x0000` (`00 06 00 00 00 33` → адрес `0x33`). Power cycle после смены не требуется.
- Таймаут ответа устройства 200 мс (прошивка ждёт 300 мс — совместимо).
- Осадки: по умолчанию непрерывное накопление без сброса; регистр `0x0107` задаёт окно накопления (сброс — записью `0` или по питанию). Паттерн per-read записи holding-регистра уже существует в прошивке (`applyXf700aRainfallWindow` в `SensorReader`).
- «7-в-1» = 7 параметров, освещённость/радиация — «один из двух» по комплектации, но карта регистров отдаёт оба.
- Питание DC12–24V, <1 Вт@12V — подтвердить совместимость с портами питания сенсоров модуля (`SENSOR_POWER_1..4`, `src/globals.h`).

### Открытые вопросы (закрыть до этапа 1)

1. Комплектация устройства: публиковать освещённость, радиацию или оба канала.
2. Имена подтипов (`sensorType`) согласовать с backend-каталогом. Важно: при именах `air_temp` + humidity-подтип прошивка автоматически добавит виртуальный VPD-канал (`VpdChannelUseCase`) — решение принять осознанно.
3. Единицы освещённости: даташит отдаёт kLux (raw/100), существующий RY-G-W — lux. Выбрать единицу и множитель (для lux multiplier = 10).
4. Семантика осадков: оставить непрерывное накопление или добавить hook сброса/окна по образцу XF700A.
5. Назначить `uid` модели и `priorityForScan`.

## Goal

- HCD6817Z определяется модулем при сканировании порта RS-485, получает адрес из диапазона `0x70–0x73` и штатно опрашивается.
- Все опубликованные каналы читаются с корректным масштабированием и уходят на backend в `hardware/update` с uid вида `<moduleUid>.<pin>.<channel>`.
- Изменения прошивки — нулевые или минимальные (максимум: rainfall-hook по образцу XF700A); поведение существующих датчиков не затрагивается.

## Non-goals / Boundaries (NOT in scope)

- **Расширение типов данных Modbus** (u32/s32/f32, порядок слов) — не требуется, все регистры u16; отдельная задача под RK900-11.
- **Новые протоколы/кадры** — активная выгрузка (registers 0x010A/0x010B), смена baud rate (0x0102), AT+GPS, электронный компас и магнитная коррекция не используются.
- **Изменение контракта backend↔firmware** — используется существующий `SensorModelHwDto`, новых полей не вводим.
- **Калибровка каналов** — заводская, пользовательской калибровки в задаче нет.

## Invariants (must ALWAYS hold)

- **INV-1:** Модель описывается только данными backend-каталога (8 `modbusRegisterConfigs`, FC03, `numRegisters=1`, `dataType="u16"`); нового decode-кода в прошивке нет.
- **INV-2:** Температура масштабируется как `raw * 0.01 − 40` (u16 raw неотрицателен, оффсет применяется после умножения).
- **INV-3:** Сканирование: пинг по `modbusPingAddress = 0x0009`, детекция — все каналы в пределах `canConnectMin/MaxValue`; адрес назначается записью FC06 в регистр `0x0000`, затем fallback на заводской `0xFF` и диапазон `0x70–0x73` по существующему алгоритму.
- **INV-4:** Каждый канал отображается в структуре модуля отдельным сенсором (`uid = entityUid.NN`) и репортится независимо; при ошибке чтения все каналы уходят `disconnected`/`value=0` — как для прочих многоканальных датчиков.
- **INV-5:** Plausibility-гейт (GDV1-3810) работает по `limitMin/MaxValue` подтипов и `canConnectMin/MaxValue` конфигов без исключений для этой модели.
- **INV-6:** Модель с 8 каналами укладывается в лимиты парсера каталога и SPIFFS-хранилища (`sensorTypes.json`) вместе с существующими моделями.

## Boundaries / Limits

| Boundary | Value | Unit | Enforced by | On violation |
|---|---|---|---|---|
| Baud rate | 9600 | bps | backend-модель + firmware | датчик не читается |
| Таймаут ответа датчика | 200 | ms | даташит; firmware ждёт 300 ms | чтение считается неуспешным |
| Регистры чтения | 0x0009–0x0010 | — | backend-модель | невалидные значения каналов |
| Адрес по умолчанию | 0xFF | — | даташит | сканирование по fallback-адресу |
| Каналов в модели | ≤ 8 (≤ 99 по uid-суффиксу) | — | firmware | каналы теряются в структуре |
| Питание | DC12–24 | V | hardware | датчик не стартует |

## Scope per system

- **Backend.** Опубликовать модель `SensorModelHwDto`: `protocol="ModBus"`, `baudRate=9600`, `modbusDeviceAddress=255`, `canScan=true`, `isSupported=true`, `modbusPingAddress=0x0009`, `registerToStoreModbusDeviceAddress=0x0000`, `writeRegistersCommand=6`, `applyAddressAfterPowerCycle=false`; 8 `modbusRegisterConfigs` (каналы 1–8) по таблице из Description, каждый с `functionCode=3`, `numRegisters=1`, `dataType="u16"` и `canConnectMin/MaxValue`; подтипы `sensorTypes[]` с `unit`, `min/maxValue`, `limitMin/limitMaxValue`. Деплой на тестовый контур.
- **Firmware.** Ожидается без изменений продакшн-кода. Верифицировать: парсинг каталога (лимиты JSON-документов на тип), размер `sensorTypes.json` при bulk-save, масштабирование `multiplier/offset` включая отрицательный оффсет температуры, сканирование (пинг 0x0009, запись адреса FC06/0x0000), синк модели `SyncSensorTypesUseCase` и построение структуры `SensorStructureUseCase::addMultiChannelModbusSensor`. По решению открытого вопроса 4 — hook окна осадков по образцу `applyXf700aRainfallWindow`.
- **Тесты (native).** Декодирование ответа из примера мануала (`FF 03 10 1A 57 0C 5F 27 83 00 11 0C 14 00 02 00 00 01 09 …`) с проверкой всех 8 масштабирований по шаблону `test_modbus_address_registers.cpp`; round-trip JSON модели (`test_sensor_types_catalog_parse.cpp`, `test_sensor_types_bulk_save.cpp`) включая размер; скан с моком `IModbusRS485`; VPD-канал согласно решению вопроса 2; plausibility-границы; при добавлении rainfall-hook — тест по образцу `test_xf700a_rainfall_window.cpp`. Раннеры регистрируются в `test/test_main.cpp`.
- **Стенд.** Ручной запрос `FF 03 00 09 00 08` через USB-RS485 и сверка с даташитом; сканирование через веб-интерфейс модуля (`USER_CAN_CONFIGURE`); проверка репортинга всех каналов в `hardware/update` и в ELK; краевые случаи: отключение датчика → все каналы `disconnected`, перезагрузка → восстановление, дубликаты адресов.
- **Документация.** Секция HCD6817Z в `doc/sensor-models.md` (шаблон — XF600A); при наличии доступа — канонический справочник в specs-репо (`docs/components/firmware/sensor-models.md`) и контракт `docs/contracts/backend-firmware/hardware-api.md`.

## Inputs / Outputs

- **In:** модель датчика из backend-каталога (`sensor_models`); ответы датчика FC03 по регистрам `0x0009–0x0010`; решения по открытым вопросам 1–5.
- **Out:** 7–8 сенсоров в структуре модуля (+ возможный виртуальный VPD); периодический `hardware/update` со значениями каналов; раздел в справочнике моделей датчиков.

## Edge cases

| Situation | Expected behavior | Protects |
|---|---|---|
| Отрицательная температура (raw < 4000) | Значение < 0 °C после оффсета −40, в пределах limitMin/Max | INV-2 |
| Комплектация без радиации (регистр 0x000F = 0) | Канал не публикуется в модели, либо 0 в пределах plausibility | Открытый вопрос 1 |
| Датчик отключился на работающем модуле | Все каналы `disconnected`/`value=0`; далее штатное восстановление (power-cycle) | INV-4 |
| Осадки копятся без сброса неделями | Монотонно растущее значение в пределах диапазона; переполнение u16 (6553,5 мм) недостижимо практически | Открытый вопрос 4 |
| Два HCD6817Z на одном порту с адресом 0xFF | Один получает 0x70+pin при сканировании; конфликт решается существующим `handleModbusAddressManagement` | INV-3 |
| Модель с 8 каналами превышает лимит JSON/SPIFFS | Обнаруживается тестом этапа «Тесты» до выкатки, а не на устройстве | INV-6 |

## Acceptance / How to verify

- [ ] Модель опубликована на тестовом backend и скачивается модулем (`SyncSensorTypesUseCase`), появляется в `sensorTypes.json` (covers INV-1, INV-6).
- [ ] Native-тест: ответ из примера мануала декодируется во все 8 значений, совпадающих с разбором даташита (27.43 °C, 31.67 %, 1011.5 hPa, 0.17 m/s, 309.2°, 0.2 mm, …) (covers INV-1, INV-2).
- [ ] Native-тест: сканирование записывает адрес FC06/0x0000 и детектирует датчик по пингу 0x0009 с проверкой `canConnectMin/MaxValue` (covers INV-3).
- [ ] Native-тесты каталога проходят с реальным payload модели, включая лимиты размера (covers INV-6).
- [ ] Стенд: датчик детектируется через веб-интерфейс, получает адрес 0x70+pin, 8 каналов видны в структуре модуля (covers INV-3, INV-4).
- [ ] Стенд: `hardware/update` несёт правдоподобные значения всех каналов; отключение датчика → все каналы `disconnected`, подключение → восстановление (covers INV-4, INV-5).
- [ ] Поведение существующих моделей датчиков не изменилось (регрессионный прогон `just test` + стенд с другой метеостанцией).
- [ ] Документация обновлена: секция в `sensor-models.md`, даташит на месте (covers Docs).
