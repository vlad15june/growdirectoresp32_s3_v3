## 2. Список ComplexRule

### Экран: ComplexRuleListScreen

Отображает все ComplexRule пользователя с текущим состоянием.

### Карточка ComplexRule

| Элемент | Описание |
|---------|----------|
| Название | Имя ComplexRule |
| Режим | Иконка Schedule (часы) или Sensor (датчик) |
| Состояние | Цветной бейдж: Idle / Running / Completed / Error / Disabled / Synchronizing |
| Количество шагов | «3 шага» |
| Приоритет | Число (если есть конфликты) |
| Триггер | Краткое описание: «07:00» или «CO₂ < 800» |

### Цвета состояний

| Состояние | Цвет | Описание |
|-----------|------|----------|
| `Disabled` | Серый | Выключен |
| `Synchronizing` | Синий | Синхронизация правил |
| `Idle` | Зелёный (dim) | Ожидает триггера |
| `Running` | Зелёный (bright) | Выполняется |
| `Completed` | Зелёный (check) | Завершён, ждёт следующий цикл |
| `Error` | Красный | Ошибка |

### Действия

- Tap → переход на экран деталей
- Long press / swipe → Enable/Disable, Delete
- FAB (кнопка «+») → создание нового ComplexRule

## 3. Создание ComplexRule — визард

### Шаг 1: Общие настройки

| Поле | Тип | Описание |
|------|-----|----------|
| Название | Text input | Имя ComplexRule |
| Режим | Selector | Schedule / Sensor |
| Триггер | Зависит от режима | Schedule: Time picker. Sensor: выбор датчика + порог. |
| Active Hours | Time range (опционально) | Окно активности |
| Приоритет | Number input | Отображается если есть конфликты с другими ComplexRule |

### Шаг 2: Добавление шагов

Список шагов с возможностью добавления, удаления, переупорядочивания.

Для каждого шага:

| Поле | Тип | Описание |
|------|-----|----------|
| Устройство | Device Picker | Выбор устройства (с индикацией конфликтов) |
| Действие | Зависит от режима | Schedule: On / Off / Pulse. Sensor: Regular / Stepper / Loop. |
| Параметры | Зависит от действия | Pulse: duration, interval, count. Loop: workingTime, waitingTime. Sensor: From/Until thresholds. |

#### UI шагов

```
┌─────────────────────────────────┐
│  Шаг 1                    [✕]  │
│  🔌 Клапан зона 1 (Модуль A)   │
│  ⚡ Action: ON                   │
├─────────────────────────────────┤
│  Шаг 2                    [✕]  │
│  🔌 Помпа (Модуль A)           │
│  ⚡ Action: Pulse 10s/30s ×10   │
├─────────────────────────────────┤
│  Шаг 3                    [✕]  │
│  🔌 Клапан зона 1 (Модуль A)   │
│  ⚡ Action: OFF                  │
├─────────────────────────────────┤
│  [+ Добавить шаг]              │
└─────────────────────────────────┘
```

### Шаг 3: Обзор и сохранение

Суммарное отображение всей конфигурации:
- Название, режим, триггер
- Список шагов с устройствами и действиями
- Предупреждения о конфликтах (жёлтый)
- Кнопка «Сохранить»

## 4. Конфигурация шага

### Schedule-режим: действия шага

| Действие | Параметры |
|----------|-----------|
| **On** | — (просто включить) |
| **Off** | — (просто выключить) |
| **Pulse** | `duration` (сек), `interval` (сек), `count` (количество циклов) |

### Sensor-режим: действия шага

| Действие | Параметры |
|----------|-----------|
| **Regular** | `from` (порог включения), `until` (порог выключения) |
| **Stepper Motor** | Параметры шагового двигателя |
| **Loop** | `workingTime` (сек), `waitingTime` (сек), `until` (порог остановки) |

### Выбор датчика (Sensor-режим)

Для первого шага — датчик триггера ComplexRule.
Для остальных шагов — свой датчик и свои пороги.

## 5. Device Picker с индикацией конфликтов

### API

Запрос `GET /api/v1/ComplexRule/devices/availability` возвращает статус каждого устройства.

### Индикация

```
┌────────────────────────────────────────┐
│  Выберите устройство                   │
│                                        │
│  ⚪ Клапан зона 1 (Модуль A)     ← OK │
│  ⚪ Помпа (Модуль A)             ← OK │
│  🟡 Вентилятор (Модуль B)              │
│     ⚠ Используется в "Вентиляция"      │
│  🔴 Нагреватель (Модуль C)             │
│     🚫 Занят правилом "Обогрев"        │
│                                        │
└────────────────────────────────────────┘
```

| Статус | Цвет | Поведение |
|--------|------|-----------|
| `free` | Белый/стандартный | Можно выбрать |
| `shared` | Жёлтый | Можно выбрать. Показать предупреждение: с каким ComplexRule делит. |
| `blocked` | Красный | Нельзя выбрать. Показать кто блокирует. |

### Когда запрашивать

- При открытии Device Picker
- При добавлении нового шага в визард

## 6. Детали ComplexRule

### Экран: ComplexRuleDetailScreen

Показывает текущее состояние и конфигурацию ComplexRule.

### Секция: Текущее состояние

```
┌──────────────────────────────────────┐
│  Фертигация                          │
│  ● Running — Шаг 2 из 3             │
│                                      │
│  ○ Шаг 1: Клапан → ON    ✅ Done    │
│  ● Шаг 2: Помпа → Pulse  🔄 Active  │
│  ○ Шаг 3: Клапан → OFF   ⏳ Waiting │
│                                      │
│  Запущен: 07:00:05                   │
│  Следующий запуск: завтра 07:00      │
│                                      │
│  [Disable]  [Edit]  [Delete]         │
└──────────────────────────────────────┘
```

### Визуализация цепочки

Последовательность шагов с текущим прогрессом:
- **Done** (✅) — шаг выполнен
- **Active** (🔄) — шаг выполняется
- **Waiting** (⏳) — шаг ожидает предшественника
- **Error** (❌) — шаг в ошибке
- **Idle** (○) — шаг не запускался

### Секция: Конфигурация

- Режим (Schedule/Sensor)
- Триггер
- Active Hours
- Приоритет
- Список шагов с параметрами

### Секция: История запусков

Список последних выполнений из `GET /api/v1/ComplexRule/{uid}/history`:

| Дата | Статус | Длительность |
|------|--------|-------------|
| 08.04 07:00 | ✅ Completed | 4мин 32сек |
| 07.04 07:00 | ✅ Completed | 4мин 28сек |
| 06.04 07:00 | ❌ Error (шаг 2) | 5мин |

## 7. Дашборд — реал-тайм состояние

### Обновление состояния

Два механизма:
1. **Polling**: `GET /api/v1/ComplexRule/dashboard` каждые 5-10 секунд
2. **Push** (если SignalR доступен): подписка на обновления ComplexRule

### Обновление на экране списка

При получении нового состояния:
- Обновить бейдж состояния
- Обновить текущий шаг (если Running)
- Анимация перехода между состояниями

### Обновление на экране деталей

При получении нового состояния:
- Обновить прогресс цепочки (какой шаг активен)
- Обновить время запуска
- При переходе в Error — показать уведомление

## 8. Редактирование и удаление

### Редактирование

- Открывает тот же визард, заполненный текущими данными
- При сохранении: `PUT /api/v1/ComplexRule/{uid}`
- Бэкенд пересоздаёт правила → модули пересинхронизируются
- Во время выполнения (Running) — **запретить редактирование**. Показать предупреждение.

### Удаление

- Подтверждение: «Удалить ComplexRule "Фертигация"? Все связанные правила будут удалены с модулей.»
- `DELETE /api/v1/ComplexRule/{uid}`
- Во время выполнения (Running) — **запретить удаление** или сначала Disable.

## 9. Валидация и обработка ошибок

### Валидация на фронтенде

| Проверка | Когда | Сообщение |
|----------|-------|-----------|
| Название пустое | Шаг 1 визарда | «Введите название» |
| Нет шагов | Шаг 2 визарда | «Добавьте хотя бы один шаг» |
| Устройство не выбрано | Шаг в визарде | «Выберите устройство» |
| Устройство заблокировано (красный) | Device Picker | Кнопка недоступна |
| Одинаковый приоритет | Шаг 1 (если shared devices) | «Приоритет N уже занят ComplexRule "X"» |
| Триггер не задан | Шаг 1 | «Выберите время/условие запуска» |

### Ошибки от бэкенда

| Ошибка | Отображение |
|--------|-------------|
| Конфликт устройств | Alert с описанием конфликта |
| Синхронизация не удалась | Бейдж Error + сообщение |
| ComplexRule в Error (runtime) | Push-уведомление + бейдж на экране |

## 10. API-интеграция

### Сервисный слой

Создать `ComplexRuleService` / `ComplexRuleApiClient`:

| Метод | Эндпоинт | Описание |
|-------|----------|----------|
| `getComplexRules()` | `GET /api/v1/ComplexRule` | Список с состояниями |
| `getComplexRule(uid)` | `GET /api/v1/ComplexRule/{uid}` | Детали |
| `createComplexRule(data)` | `POST /api/v1/ComplexRule` | Создание |
| `updateComplexRule(uid, data)` | `PUT /api/v1/ComplexRule/{uid}` | Обновление |
| `deleteComplexRule(uid)` | `DELETE /api/v1/ComplexRule/{uid}` | Удаление |
| `enableComplexRule(uid)` | `POST /api/v1/ComplexRule/{uid}/enable` | Включение |
| `disableComplexRule(uid)` | `POST /api/v1/ComplexRule/{uid}/disable` | Выключение |
| `getDashboard()` | `GET /api/v1/ComplexRule/dashboard` | Дашборд |
| `getHistory(uid)` | `GET /api/v1/ComplexRule/{uid}/history` | История |
| `getDeviceAvailability()` | `GET /api/v1/ComplexRule/devices/availability` | Доступность устройств |

### Стейт-менеджмент

- Хранить список ComplexRule и их состояния
- Обновлять при получении данных с бэкенда (polling/push)
- Кэшировать конфигурацию для offline-просмотра
