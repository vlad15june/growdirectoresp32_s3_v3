# Урок 8. RS-485 и Modbus RTU: кадры, CRC, сканирование датчиков

## Теория

RS-485 — полудуплексная дифференциальная шина: несколько устройств на A/B, говорят
по очереди. Прошивка — мастер шины, датчики — слейвы. Базовый кадр Modbus RTU:

```text
[addr][func][reg hi][reg lo][qty hi][qty lo][crc lo][crc hi]
```

- Чтение holding: FC03, input: FC04; запись одного регистра: FC06; нескольких: FC16.
- CRC16 (полином 0xA001, инициализация 0xFFFF), в кадре — младшим байтом вперёд.
- Между кадрами — тишина ≥ 3.5 символа; перед запросом прошивка дренажит линию
  (`quiesceBus`), чтобы не принять хвост чужой транзакции за ответ.
- Ответ валидируется жёстко: CRC, адрес ответчика, function code, byte count.
  Мягкий "alive"-пинг (адрес + FC) — только в процедурах опознавания.

Как датчик попадает в систему (всё data-driven, без кода под конкретную модель):

1. В backend-каталоге (`sensor_models`) модель с `modbusRegisterConfigs`
   (reg, numRegisters, multiplier, dataType u16/s16, canConnectMin/Max, canScan).
2. Сканер (`StartupSensorScanUseCase`) перебирает свободные порты и адреса,
   пробует конфиги моделей; при ответе — `scanSensor()`:
   пинг адреса + чтение каналов с проверкой диапазона.
3. Усыновление: создание сущности `SensorEntity`, выдача адреса из диапазона
   `0x70–0x73` (`MODBUS_ADDRESS_MIN/MAX` в `constants.h`), публикация structure.

Реальный кейс из практики (CC-FL-120W): счётчик отвечает только на двухрегистровое
чтение — однорегистровый пинг молчал, и датчик не усыновливался. Решение (коммит
GDV1-3535): после пустого пинга один retry «широким» кадром (2 регистра) с фиксированной
паузой 200 мс (`wideProbeSent` в `ModbusSensorReader.h`). Урок: даташит ≠ поведение,
пробу всегда проверяйте осциллографом/логом на реальном железе.

## Разбор в прошивке

- `src/Infrastructure/Adapters/Sensors/HardwareSensors/ModbusSensors/ModbusSensorReader.h` —
  `readRegister` (запрос/валидация/декод 1-2 регистров), `pingAddress` + wide-probe,
  `writeSensorAddress` (FC06/FC16 + верификация + фолбэки).
- `src/Core/Domain/UseCases/Sensors/StartupSensorScanUseCase.h` — лестница сканирования
  (cheap probe -> подтверждение -> усыновление).
- `src/Core/Domain/Data/Entities/Sensor/ModbusRegisterConfig.h` — конфиг канала.
- `src/constants.h:141-142` — диапазон выдаваемых адресов.

## Задание

Напишите standalone-утилиту (host, Python или C++ native) — мини-сканер шины:

1. Функция `crc16(data)` по спецификации выше; самопроверка на кадре
   `01 03 00 00 00 02` → CRC `C4 0B` (как в даташите CC-FL-120W).
2. Перебор адресов 1–247: кадр `[addr] 03 00 00 00 02`, ожидание 300 мс, печать
   адресов, ответивших корректным CRC.
3. Для найденного устройства — чтение 2 регистров и вывод значения × 0.01.

Сравните с тем, как это делает `mbus_addrscan.py` из отладки CC-FL-120W — там же
готовый эталон через MQTT `SerialWrite`.
